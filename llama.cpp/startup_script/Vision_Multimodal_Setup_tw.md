# 為什麼 llama-server Router 模式下視覺模型不會生效（以及如何修正）

## 問題描述

當你以 **router 模式**（也就是用 `--models-dir` 啟動、讓 one-click 啟動器可以熱切換多個模型的那種模式）執行 `llama-server` 時，如果視覺／多模態的 GGUF 模型沒有正確擺放，它會**悄悄退化成純文字模式**，不會有任何錯誤訊息——伺服器只是不接受圖片輸入，而 `/props` 端點會顯示該模型 `"modalities": { "vision": false }`。

這**不是啟動腳本本身的錯誤**，而是 llama-server router 模式偵測多模態投影器檔案的機制就是這樣設計的。

## 根本原因

在 llama.cpp 裡，一個支援視覺功能的模型其實是**兩個獨立的 GGUF 檔案**：

1. 主要的語言模型（例如 `Qwen3-VL-8B-Q4_K_M.gguf`）
2. 多模態投影器（**mmproj**）檔案，負責把圖片編碼成 embedding（例如 `mmproj-Qwen3-VL-8B-F16.gguf`）

在 router 模式下，llama-server 會掃描 `models` 資料夾，並自動把這兩個檔案配對在一起——**但必須同時滿足以下兩個條件**：

- 主模型檔案與其對應的 mmproj 檔案**必須放在同一個獨立的子資料夾裡**（不能散放在 `models` 根目錄，也不能和其他模型的檔案混在同一個資料夾）
- 投影器檔案的檔名**必須以 `mmproj` 開頭**

只要其中一個條件不符合，mmproj 檔案就會被忽略，或是被誤判成一個無關、無法使用的獨立「模型」——而實際的語言模型則會以純文字模式載入。

## 正確的目錄結構

```
models/
├─ Qwen3-14B-Instruct-Q4_K_M.gguf              ← 純文字模型：直接放在根目錄就沒問題
│
├─ Qwen3.8-27B/                                  ← 視覺模型：需要自己獨立的資料夾
│  ├─ Qwen3.8-27B-Q4_K_M.gguf
│  └─ mmproj-Qwen3.8-27B-F16.gguf
│
└─ Qwen3-VL-8B/                                  ← 另一個視覺模型，也要有自己的資料夾
   ├─ Qwen3-VL-8B-Q4_K_M.gguf
   └─ mmproj-Qwen3-VL-8B-F16.gguf
```

## 常見錯誤

| 錯誤做法 | 結果 |
|---|---|
| 主模型 `.gguf` 和 `mmproj-*.gguf` 都直接丟在 `models/` 根目錄 | 無法配對——模型以純文字模式載入 |
| 多個模型的 mmproj 檔案共用同一個資料夾 | Router 會把 mmproj 配對給該資料夾裡第一個找到的模型檔案，可能配對到錯誤的模型 |
| 投影器檔名沒有以 `mmproj` 開頭（例如改成 `vision-encoder.gguf`） | 完全不會被辨識為投影器 |
| 主模型和 mmproj 分別放在不同的子資料夾 | 無法跨資料夾配對——router 只會在**同一個資料夾內**尋找配對 |

## 如何確認生效

1. 重新啟動伺服器，觀察啟動 log 裡關於自訂 preset／偵測到的模型的訊息。
2. 模型載入完成後，查看 router 的 `/props`（或 `/props?model=<模型名稱>`）端點，確認出現：
   ```json
   "modalities": { "vision": true }
   ```
3. 在網頁介面中，選擇具備視覺能力的模型後，聊天輸入框旁應該會出現圖片上傳／附加檔案的圖示。如果沒有出現，代表配對失敗。

## 快速檢查清單

- [ ] 每個視覺模型在 `models/` 底下都有**自己獨立的子資料夾**
- [ ] 該子資料夾裡**只放**這個模型的檔案＋對應的 mmproj 檔案（不混入其他模型的檔案）
- [ ] 投影器檔名**以 `mmproj` 開頭**
- [ ] 重新啟動後，`/props` 顯示該模型 `"vision": true`
